#### 技术路线

- Office 使用 LibreOffice 独立可选运行时，用于 DOCX、PPTX、XLSX 转 PDF，以及 RTF、ODT、ODS 等原生转换；不经 OCR 或语义 IR 重建。采用无界面转换和独立用户配置目录。参考 [LibreOffice 命令行文档](https://help.libreoffice.org/latest/en-GB/text/shared/guide/start_parameters.html?DbPAR=BASIC&System=WIN)。
- 语义格式使用 Pandoc 独立可选程序，用于 Markdown、HTML、DOCX 和 EPUB 的适用转换，不宣传无损排版往返；分发保留对应许可和源码材料。参考 [Pandoc 许可](https://raw.githubusercontent.com/jgm/pandoc/main/COPYRIGHT)。
- DOCX 编辑使用现有 ZIP 能力及命名空间感知的 OOXML 解析，按对象定向修改目标部件，保留未涉及的部件与关系；不使用全局字符串替换。复杂对象无法安全编辑时明确限制。
- PDF 继续使用 PDFium，增加 qpdf 结构处理适配。批注和页面内容操作使用实际支持的写入接口；不将渲染能力当作完整内容编辑能力。参考 [qpdf 官方说明](https://qpdf.sourceforge.io/)。
- 图像处理扩展现有 Rust image，按所需算法加入 imageproc，基础版不引入 libvips。
- PDF 转 DOCX 建设插件内专用版面重建适配器，复用 PDFium 页面信息与 OCR 结果，输出真实段落、表格、图片及样式。默认不引入依赖 PyMuPDF 的 pdf2docx，避免未经确认改变专有插件的许可安排。参考 [pdf2docx 依赖清单](https://raw.githubusercontent.com/ArtifexSoftware/pdf2docx/master/requirements.txt)和 [PyMuPDF 许可](https://pymupdf.readthedocs.io/en/latest/about.html)。
- Markdown 和 HTML 的富文本交互采用 ProseMirror，源码视图处理原始文本；它不承担 DOCX 无损往返职责。

#### 转换矩阵和处理边界

转换能力矩阵按具体方向维护，记录输入、输出、后端、安装要求、保真或可编辑等级、验证样本与限制，不提供“任意格式互转”。

- Office 原生路径覆盖 DOCX、PPTX、XLSX 转 PDF；文档格式覆盖 DOCX 与 RTF、ODT 的适用转换；表格格式覆盖 XLSX、ODS、CSV 的适用转换。
- 语义路径覆盖 Markdown、HTML、DOCX 之间的适用转换，以及 PDF 解析结果和上述适用格式到 EPUB 或结构化输出；TXT 按纯文本处理。
- PDF 转 DOCX 提供视觉优先、编辑优先、页面图像保留三种模式，不将整页图片嵌入称为高保真可编辑转换。
- 图片转 DOCX 提供原样嵌入、可编辑正文、复杂版面重建三种模式。原样嵌入不调用 OCR；正文模式恢复段落、标题、列表和简单表格；复杂模式标明实验性及已验证范围。
- CSV 导出明确选择工作表和编码，说明其不保留样式。指定图片大小无法达到时报告限制，不静默降低到未声明的质量。
- 未安装后端时显示安装入口和缺失原因，不静默改用质量不同的路径；缺失某个可选后端不阻断其他工具。
- 默认另存，不覆盖原始文件；宏和外链不自动执行或更新；第三方进程受超时、取消和进程树管理约束。原生 backend 和 worker 不宣称具备 OS 安全沙箱。
- 工作流按步骤保存状态；无法中途暂停的外部操作在当前步骤完成后暂停，并在界面如实说明。重试由用户明确发起，不自动重复已提交输出。
- 本轮不建设完整 Office 编辑器、图形节点工作流、向量数据库或 RAG 问答系统。敏感内容永久涂黑不属于本轮必做范围；不能以黑色覆盖层冒充安全清除。

#### OCR 调查与集成

先检查现有缩放、检测阈值、裁剪、字典、ONNX 张量及后处理，再比较新模型，不将缺字问题直接归因于模型能力。

- GLM-OCR 为首个集成目标；HunyuanOCR-1.5 为重点对照，PaddleOCR-VL-1.6 为复杂版面对照。
- 优先验证 llama.cpp 的 Windows 运行路径，按任务启动，逐页处理，完成后释放模型；不要求用户安装 Python、Conda 或 CUDA 开发工具包。目标设备按用户提供的 Windows 11、i9-14900HX、32GB RAM、RTX 5070 Laptop 8GB 验证，本机已只读确认显卡型号及约 8GB 显存。参考 [llama.cpp 多模态支持](https://raw.githubusercontent.com/ggml-org/llama.cpp/master/docs/multimodal.md)。
- GLM 代码、权重和配套版面组件分别核对许可；Hunyuan 含地域限制，默认只安排本地对照及用户自行导入，不纳入通用公开权重附件。参考 [GLM 官方仓库](https://github.com/zai-org/GLM-OCR)、[Hunyuan 许可](https://raw.githubusercontent.com/Tencent-Hunyuan/HunyuanOCR/main/LICENSE)和 [Paddle 模型卡](https://huggingface.co/PaddlePaddle/PaddleOCR-VL-1.6)。
- 引擎统一描述模型资源、能力、请求、结果、错误和运行状态。识别结果保留引擎及版本、页面和区域映射；模型没有提供置信度时不伪造置信度。
- 新模型通过目标机质量和资源验证后才成为推荐方案。PP-OCR 保留为可明确选择的低资源方案，不用它掩盖新引擎集成失败。
- 公式不可靠时保留原图并标记待校对，支持局部重识别及人工修正。现有九式 4/9 等记录只作为历史基线材料，不冒充本轮实测。
- 大型模型和运行时通过宿主资源管理，由用户显式下载或离线导入；不随基础插件包内置，不在启动、状态查询时自动联网下载。

## 四、主题底座、编辑器与 P5R

### 通用底座和公开接口

扩展现有主题协议，不建立第二套插件运行时。

### P5R 主题

作为主题管理插件中的完整主题分发，phantom 名称、预设及素材不进入宿主实现。

- 首页优先实现非对称主菜单、原创工具图形、拼贴标题、背景联动和选中动效。
- 菜单模式覆盖首页、市场及设置入口；工作台模式覆盖任务中心和插件工作区。
- 统一按钮、标签页、弹窗、输入框、选择控件、列表、进度、通知和结果反馈。
- Document Engine 使用文件导航、正常比例内容区、属性区及任务区；MC 使用紧凑文件与转换信息布局。
- 文件名、正文、表格、公式和错误信息保持正常比例、可读和可复制。
- 支持完整、简化、关闭动效，遵循系统减少动态效果设置；主题切换清除旧样式和动画，不影响真实任务状态。
- 支持鼠标、方向键、Enter、Esc、Tab 和可见焦点；中文输入法、弹窗焦点及窗口操作保持正常。
- 不使用人物、剪影、游戏 Logo、游戏字体、官方贴图或任何音频。
- 市场的主题适配不增加下载网络设置入口，始终遵守本计划第二节的市场范围。

1. **既有门禁**：宿主执行 npm run check、npm run build；宿主、runner 和 CI 列出的 crates 使用锁定依赖执行 fmt、clippy、test。各插件执行已有类型检查、测试及构建，不为纯文案或简单样式改动新建重复测试体系。
2. **生命周期**：逐个验证安装、升级、启停、真实重试、切页恢复、取消、退出应用、重启、卸载及重装。启动失败不显示已运行，退出不改变用户启用选择；安装记录 ID 与清单身份不同的样例必须通过。卸载后检查代码、安装缓存和独占资源确已删除，用户数据仍可恢复。任务输出沿用现有提交与取消确认机制。
3. **市场和设置**：市场仅有官方稳定版与测试版目录，搜索直接输入；取消导入不报错；批量失败可追溯到具体包；切换渠道和缩放后工具栏不挤压。下载网络仅在设置页调整，市场无下载网络设置或设置入口。
4. **文档质量**：真实样本覆盖中英文、复杂表格、浮动图片、分节、页眉页脚、目录、公式、多栏和扫描件，同时检查结构、可编辑性与渲染，不能只检查文件生成。
5. **DOCX 定向编辑**：分别修改正文、表格、图片和标题样式，验证关系有效、未编辑部件保留、办公软件正常打开，无明显非预期版面破坏。
6. **OCR 基本回归与后续专项**：当前仅验证既有识别入口、任务、取消和资源选择没有回归；OCR 不作为主要验收项。40 页对照集和新模型质量评估移至其他任务完成后的专项，记录字符错误、漏字漏行、公式、表格、耗时、内存、显存和失败率。未经实测改善的新引擎不成为推荐方案，不用排行榜或实验性标签冒充质量通过。
7. **性能与文件边界**：覆盖长文档、大图、多页 TIFF、批量任务、命名冲突、外部进程超时和取消；既有 2000 页限制不计作已经通过该规模压力测试。外部文件处理保留必要的解压、路径、内容规模和输出保护。
8. **界面人工验收**：覆盖 800×600 最小窗口，以及 1280×720、1366×768、1440×900、1920×1080 和 Windows 125%/150% 缩放；检查键盘、中文输入、长路径、快速切页、任务中换主题、减少动效及恢复默认主题。
9. **发布条件**：核心功能全部稳定通过；实验性功能具有实际结果、已验证适用范围和明确限制。任何未完成必需项都阻塞正式发布。原生桌面效果和无法自动完成的真实办公软件检查单独记录，不将构建通过等同于完整验收。
