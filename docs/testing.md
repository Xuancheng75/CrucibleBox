# Next 3.0 测试指南

本页区分开发检查、固定宿主验收和原生人工操作。当前补完结果见 [补完记录](2.2.0-completion-audit.md)，历史 beta.6 结果见 [P7/P8](2.2.0-p7-p8.md)，原安全告警与用户授权的替代实现见 [事件记录](2.2.0-security-incident-20261107.md)。不能据验证规格推断未执行的项目已通过。

## 开发检查

按 development.md 设工作区 TEMP/TMP/TMPDIR、npm cache 和 CARGO_TARGET_DIR。运行 npm run check、npm run build；宿主与 runner 执行 fmt --check、Clippy --all-targets -D warnings、锁定依赖 test。独立 crates 按现有 CI 清单执行，native runtime 使用 test-backend feature。不运行系统安装器测试。

2026-11-13 用户批准的唯一安装器测试例外限 GitHub 托管的一次性 Windows 虚拟机，手动工作流默认关闭，不在本机执行；方案及真实状态见 [签名切换验收](2.2.0-updater-transition.md)。

先构建 runner 并暂存到与 MSVC/GNU 目标匹配的 binaries 文件，再运行宿主集成。不要让旧 sidecar 覆盖新 runner。源码门禁、进程集成、打包和原生人工验收分别记录。

## 固定宿主验收

程序目录、两个 EXE 摘要、profile、源码提交与版本写入固定清单。插件在外部独立构建，只经公开安装、资源、renderer/backend/service/任务 API 交互。需要测试观察者直接读取测试库时注明只读诊断用途，不能把这种入口放入插件 SDK。

P5/P6 已验证四类诊断插件、两个真实业务负载、生命周期与数据保留。复跑工具保存在独立插件仓库，见 [范围与证据](2.2.0-p5-p6.md)。真实 WebView/iframe 挂载不等于已人工确认窗口布局；业务域模块加真实存储也不能冒称编辑器界面已操作。

## P7 执行清单

以下是验证规格，逐项实测结果以执行记录为准：

| 项目          | 负载与通过条件                                                                                                                                                                                                                     |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 插件加载      | 64 个启用插件、16 个实际挂载页面，记录启动、加载失败、资源预算与停止结果；超出已有会话上限明确拒绝。                                                                                                                               |
| 高频 RPC      | 至少 10000 次有序调用及 16 路并发样本，核对每次关联、结果和重放拒绝；记录吞吐与 p50/p95/p99，不将调试协议开销等同纯宿主开销。                                                                                                      |
| 注册表        | 兼容升级后可发现新增接口；不兼容升级拒绝；无关损坏包不传播到正常消费者；选中执行包篡改仍拒绝。                                                                                                                                     |
| Provider 故障 | 实际进程退出使相关调用失败，无关平台/服务仍可用；后续显式重启或调用的恢复单独记录。                                                                                                                                                |
| 任务          | 覆盖运行中取消、提交窗口、超时、后台恢复与进程树停止；排队取消另以任务运行时用例验证。当前每插件任务资源独占，全局最多 16 个 Service/Task 实例，资源不足须明确失败，不强行承诺八个原生任务同时运行。只有确认停止后才计入取消成功。 |
| 大文件        | 64 MiB 校验下载与受管分块读取，比较实际字节/摘要，记录进度；失败、取消与所有权拒绝不能留下伪成功输出。                                                                                                                             |
| 数据          | 隔离的旧记录/配置/KV/标记/用户文件迁移及配对恢复；原始数据保留，冲突不覆盖；实际生产迁移另行确认。                                                                                                                                 |
| 权限          | 原生信任未接受、未声明权限、伪造会话/owner、跨插件引用、过期和停用会话、路径与重解析点拒绝。                                                                                                                                       |
| 双实例        | 同一 profile 第二宿主在数据库初始化前拒绝，独立 profile 可独立运行；退出/崩溃后锁释放。旧宿主不理解新锁时须先显式关闭。                                                                                                            |
| 长时          | 连续 60 分钟、每秒 5 次调用，定期续签会话并抽样主进程/子进程私有内存、句柄、CPU 和 PID。记录完整时长及增长趋势，不把短测试称长稳。                                                                                                 |

性能数字必须带候选摘要、优化/调试模式、插件/页面数、机器内存和样本数。若预先设置观察预算，应注明它是本机验收阈值，不是所有电脑的性能承诺。发现异常先保留现场并定位，不能通过删检查、换宿主或重置用户数据获得漂亮结果。

## 原生人工清单

对完成扫描的固定候选，由用户确认：启动时不再闪现“外观”菜单栏；设置页与 Ctrl+Alt+Shift+R 恢复主题；浅/深主题、缩放、键盘焦点；插件导航与命令位置；长任务取消提示；日志导出；正常窗口关闭和重开。逐项填写通过、问题或未测，记录实际版本和样本，不默认同意或替用户补写通过。

2026-11-08 用户以隔离 beta.6 启动入口确认：菜单栏移除、设置页和快捷键主题恢复、正常关闭重开通过。其余手动项目尚无回执，不从自动 iframe/IPC 结果推断。完整小时、制品安装和具体人工回执的归档见 [P7/P8](2.2.0-p7-p8.md)。
