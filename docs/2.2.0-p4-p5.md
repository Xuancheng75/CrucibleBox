## P4 公共能力

| 服务 | 实际入口与边界 |
| --- | --- |
| File | files.choose 授予受管文件引用。files.info/list 提供元数据和单层清单，最多枚举 128 项，清单跳过重解析点。files.read 与分块读取检查打开句柄的最终路径。任务可用 files.writeResult 写入最多 24 KiB 二进制结果，或通过 files.publish 复制插件数据区内生成的文件。输出经过暂存和发布日志，文件引用按 owner 保存。 |
| Network | 使用宿主代理与 TLS 策略。network.fetch 提供有界文本请求响应。network.download 在已授权任务中流式下载二进制，按调用方提供的字节数和 SHA-256 校验，发布后返回文件引用。最大 1 GiB，每次读块之间检查取消和期限，并记录进度。 |
| Process | process.run 需要 process:run 权限与插件自己的执行任务。输入是已声明的工具 ID、参数数组、可选 Base64 stdin 和超时。每次执行有私有临时目录，stdin 上限 4 KiB，stdout 和 stderr 分别上限 8 KiB，输出返回 Base64 与退出码。并发复用已有 Provider 任务资源。Windows Job Object 管理超时、取消和进程树清理。 |
| Runtime、Resource | resources 声明版本范围，tools 指向其中一个资源 ID 及其清单中登记的 Windows EXE。runtime.list 查询工具及已安装版本，显示可选资源缺失。安装、验证、更新选择、卸载与权限沿用版本化资源仓库。执行前核对获批资源及文件摘要。 |
| Storage | 配置、私有 KV、批量事务和大值分块使用原 SQLite 命名空间。storage.usage 报告使用量和 32 MiB 配额。超额增长在事务中回滚，允许减少旧数据用量。插件可用同一事务写入数据和自己的版本标记。 |
| Logging | logging.write 支持错误码和有界上下文。宿主记录 renderer、QuickJS 或 native 来源、请求与任务关联，数据库保存插件身份、时间和等级。日志页可将当前筛选结果导出为 JSONL。 |

工具资源必须属于插件的已批准依赖，资源类型为 runtime，并接受本地代码信任。工作目录、可执行文件与环境由宿主管理，调用方通过参数数组传值。工具拥有当前用户的系统权限，进程隔离用于生命周期管理。底层系统操作返回控制权后才能检查取消。进程结果保留实际退出码，任务成功表示该次进程调用完成，业务调用方仍须判断退出码。

~~~json
{
  "permissions": ["process:run"],
  "resources": [
    {
      "id": "python-runtime",
      "version": { "min": "3.14.0", "maxExclusive": "3.15.0" },
      "optional": true
    }
  ],
  "tools": [{ "id": "python", "resourceId": "python-runtime", "entry": "python.exe" }]
}
~~~

通过任务通道调用 Provider 或自己的后端方法，后端在执行中调用 api.process.run 或 api.network.download。SDK 在上下文内关联调用者，结果可从任务中心查询。运行环境以独立资源发布，缺失时由用户在资源页安装并批准。本轮覆盖受管结果写入、校验下载和资源工具启动。通用目录改写与监听、断点续传、上传、WebSocket 和系统级运行时管理属于后续能力扩展。

## P5 界面与工具链

导航标题用于工作台和命令搜索。插件使用独立 iframe 与公开 SDK。contributes.commands 可带 keywords 和 placements，工作区支持 toolbar、sidebar、contextMenu 和 status。各位置调用同一个插件的后端命令。执行时重新核对安装状态。插件设置使用通用配置表单，文件处理、主题变化、确认窗口、通知及任务继续走公开接口。

@cruciblebox/next2-ui 复用主题变量，提供文件选择、任务与存储辅助和 renderStatus。页面可使用 HTML 表单与 .ob-button、.ob-input 等主题钩子。表单字段使用 label，状态文本具备屏幕阅读器语义，操作期间显示加载反馈。配置、权限和宿主状态经消息桥交付，插件可选择自己的界面框架。

QuickJS Provider 通过 defineProvider 在激活函数获得公开客户端。Manifest 声明服务方法及输入输出 Schema，业务方法由独立插件实现。原生插件使用独立 Rust SDK。构建工具与 API/UI 包可安装到独立目录。

~~~text
cruciblebox-next2 init sample-provider provider
cd sample-provider
npm install
npm run build
npm test
npm run pack
~~~

模板包括 frontend、js、provider 和 native。原生模板通过 --native-sdk 指定解包后的公开 SDK，Cargo 目标目录设在插件项目内。npm test 使用 CLI 的 check 验证清单、文件清单、字节数和摘要，随后可将 ZIP 导入匹配宿主完成进程和业务验收。
