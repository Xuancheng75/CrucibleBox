# 插件能力与开发边界

Next 3.0 开发分支的 Capability Descriptor、授权和 SDK 使用见 [P0/P1 验收](2.2.0-p0-p1.md)。事件订阅、请求取消、任务超时与文件分块见 [P3 IPC、事件与任务](2.2.0-p3.md)。

65 个公共方法的权限、上下文与参数/返回类型见自动生成的 [API 索引](plugin-api-reference.md)，Provider 实现与消费示例见 [Provider 指南](provider-guide.md)。

Next 3.0 开发候选执行 Manifest 7、API 7、wire 5。JS API/UI 为 7.0.0-beta.2，CLI 为 3.0.0-beta.2，Rust SDK 为 0.2.0-beta.2。原有清单形态最低宿主为 2.2.0-beta.1；带工具、下载权限或命令位置/关键词的清单最低为 2.2.0-beta.2，新模板自动采用该版本。契约来源为 contracts/next2/contract.json，公共包位于 packages/cruciblebox-next2-*。候选版本和正式兼容规则见 [版本策略](2.2.0-p0-p3-recheck.md#版本与兼容策略)，新增 API、工具声明、Provider SDK 与独立构建流程见 [P4/P5](2.2.0-p4-p5.md)。

| 插件形态 | 执行环境                     | 适用范围                                                       |
| -------- | ---------------------------- | -------------------------------------------------------------- |
| 纯前端   | sandbox iframe、浏览器 JS    | 表单、计算、可视化与本地界面工具                               |
| JS 后端  | 独立 QuickJS runner          | 通过 SDK 使用存储、配置及已声明的平台/服务能力；不提供 Node.js |
| 原生后端 | Windows x64 独立 EXE、wire 5 | 文件处理、外部工具、原生库与长任务；属于可信本地代码           |

平台提供：插件配置与私有 KV（含有界分块/事务）、后台任务及进度/暂停/取消、文件选择和 owner 绑定引用、结果发布、代理路由与 HTTPS 请求、剪贴板、宿主主题预览/提交/回滚、对话框和通知、独立资源包安装/下载/校验/挂载、声明式服务依赖及版本检查。

2.2.0-beta.2 增加文件元数据与单层目录枚举、受管二进制结果写入、任务内校验下载、已获批运行时工具执行与状态查询、32 MiB KV 配额/用量，以及结构化日志和筛选结果导出。命令可声明工具栏、侧栏、菜单和状态栏位置。各 API 的上下文、权限、大小上限与错误返回以公开契约为准。

2.1.1 的通用任务恢复补修保存最近 200 条执行结果、起止时间与归属，不保存任务请求参数；重启后仍以核心任务状态和 owner 为准，不自动重跑。补修前未保存的完整结果无法追补：列表带 `resultUnavailable`，成功任务的 `tasks.get` 明确报错，已有输出仍可在任务中心核对。输出已提交而执行收尾失败也明确报错，不能将此类失败当作正常结果。详见 [补修与验证边界](2.1.1-task-result-fix.md)。

2.2.0-beta.3 统一 tasks.get/list 的完成时间来源：已保存的执行结果记录在当前进程及重启后均提供同一个 completedAt。输出提交可能早于结果持久化；completedAt 为 0 时执行收尾仍在进行，轮询方应等待其大于 0。执行收尾失败继续明确报告，不把输出已提交当成完整执行成功。见 [P6 修复与复验](2.2.0-p5-p6.md)。

插件可声明导航、命令和文件处理扩展名；命令面板执行 manifest 映射的后端方法。安装、升级、停用、卸载及退出均经通用生命周期；代码与资源版本化，用户数据位置稳定。签名/发布者、原生代码和权限扩张在安装阶段确认。

新插件只开发、构建与分发自己的代码和资源包，无需修改或重新编译宿主。只有新增当前契约没有的平台能力，才需要独立提出宿主变更。插件名称、业务方法和算法不得写入宿主分支或白名单。

不承诺：旧 API 执行兼容、Node.js 运行时、跨平台原生 ABI 或 OS 安全沙箱。插件业务是否正确需单独验收，底座测试通过不能替代业务验收。

后端在首个能力请求使用 `backend-seq-N`（正整数递增）选择有序请求。Rust SDK 在同一输出锁内分配并发送编号，JS runner 分配 wire 编号并还原客户端关联 ID。宿主保存序列高水位及有界在途请求，拒绝旧编号。采用不透明编号的客户端有 4096 次会话预算，不能中途换编号清空记录。普通调用有执行期限，长任务使用任务通道。

## 通用主题设计 v2

原有 `{id,name,mode,tokens}` 主题继续工作；新增可选 `design:{version:2,...}`。`layout` 提供侧栏、顶部和菜单导航、密度、宽度、间距；`components` 提供圆角、边框、阴影、按钮倾斜和标题字重；`layers` 提供形状、图片及纯文本装饰，作用于外壳、首页或工作区。宿主不包含业务主题名称或素材。层数最多 32、字体最多 8、素材最多 32。

`@cruciblebox/next2-ui` 的 `createClient(context)` 协商样式版本 2；直接使用 API 包的界面可显式调用 `context.enableThemeStyle?.(2)`。未协商的旧界面仍只收到原有主题变量。新样式切换、回滚、销毁会清理旧规则、字体与装饰层；缓存页面隐藏时暂停主题动画。系统“减少动态效果”优先于完整动效，关闭动效时停止主题动画和过渡。

新权限 `theme:assets` 允许导入和浏览用户主题素材，独立于 `theme:read/write`。先以 `files.choose` 获得文件引用，再调用 `theme.assets.import({fileRef,license,notice?,source?})`；`get(id)` 返回包含许可正文的单个素材，`list({after?,limit?})` 每页最多 16 个且不带许可正文。支持静态 PNG/JPEG/WebP（单件 8 MiB、32M 像素）和 TTF/OTF/WOFF2（单件 32 MiB）；每个主题的图片合计不超过 64M 像素。不导入 SVG、脚本或动画图片。字体要求开放许可标识和许可正文（UTF-8 最多 16 KiB），导出主题时必须保留。素材归用户数据，卸载导入它的插件后继续保留。应用主题时，素材地址会进入参与渲染的页面；此机制不承诺对已显示素材保密。

`design.assets` 声明素材 ID；图片层和字体引用已声明的 ID。CSS 中仅接受 `url("asset:<id>")`，由宿主解析为专用素材地址，不接受网络、本地路径、data URL、`@import` 或自定义 `@font-face`。CSS 经解析后限定在主题根节点内，关键帧与引用一并改名；动画名称必须静态声明，不接受通过变量间接指定动画名。额外 CSS 最多 8192 字符，编译样式不超过 48 KiB，完整样式消息不超过 64 KiB；不支持的语法明确报错，不静默应用半个设计。

`theme.assets.importBundled({path,license,notice?,source?})` 可将调用方插件包内的素材导入用户素材库。`path` 必须精确匹配调用方已批准并完整核验的安装清单，解析后仍处于其代码目录；不接受其他插件或任意本地文件。此接口沿用 `theme:assets` 权限、现有格式/大小/字体开放许可规则和卸载保留规则，不增加路径读取权限。插件可以随包携带开源字体并在用户选择预设时使用此接口；用户导入仍使用原文件选择接口。

缓存界面可使用可选的 `context.onVisibilityChanged?.(listener)` 订阅显示状态，注册时立即返回当前值，并返回取消订阅函数。页面隐藏会撤销其尚未保留的主题预览，并拒绝隐藏期间的预览、保留及设置操作；草稿和已经保留的主题不受影响。素材加载中离开也不会晚到应用预览。

主内容区提供 `.cbx-page-stage[data-page-transition]` 与 `.cbx-page-transition`（含两个装饰 span）作为通用主题转场挂点，默认隐藏。仅装饰节点按页面或活动插件切换重新创建，保留页面与 iframe 实例不重新挂载。主题可用 CSS 定义遮幕等效果；`--ob-page-transition-display` 在完整动效且开启页面过渡时为 `block`，在减少/关闭动效时为 `none`。遮幕独立裁剪且不接收输入，不能导致滚动范围扩大或阻挡操作。菜单/侧栏的展开选择仅由用户控制，页面切换不再自动折叠。

同一视口提供 `data-page-direction="up|down|left|right|none"` 和单位方向变量 `--ob-page-direction-x/y`：侧栏按工作台、市场、任务、设置的顺序前进时向上，返回时向下；顶部导航按左右顺序；进入或切换插件向左，离开插件向右。`logs` 与任务属于同一层级。视口是 size 查询容器，主题可用 `100cqw/cqh` 作为移动距离。页面变化时，宿主在绘制前只重启直接附在 `.ob-main-content` 上的动画，不移动或重建其页面/iframe 子树；需要整页移动时应动画这个滚动容器，避免动画长内容时扩大滚动范围。完整、减少、关闭和无过渡仍由既有主题动效规则控制。

需要旧页/新页交接时，主题可在根节点设置 `--ob-page-handoff:1`，并给 `.ob-main-content` 设置 `view-transition-name:cbx-page`。宿主仅在完整页面动效下使用浏览器同文档过渡，将同一事件的页面/插件变更合并提交；旧页图像由浏览器临时保留，现有 iframe 不克隆或重新挂载。主题可分别设置 `:root::view-transition-old(cbx-page)` 和 `:root::view-transition-new(cbx-page)`；解析器只接受单个、长度受限的简单名称参数，仍拒绝变量、选择器及其他未知 Raw 语法。方向变量也位于根节点，供两个过渡图像使用。过渡期间内容区暂不接收操作，侧栏与顶栏仍可切换目标；后来的导航取代未提交的旧目标，关闭活动插件会使其失效。更换主题会结束正在播放的交接；减少动效或不支持此能力时正常直接导航。

通用卡片可使用 `data-card-variant="1|2|3|4"` 和 `.ob-card-heading`。设置的四个区域分别提供四个变体；市场与任务按完整条目集合均衡混排，条目顺序不变，同一集合排序或筛选时样式保持。插件目录按钮的 `aria-pressed` 表示当前预览选择。

主题 v2 首次随 2.1.1 交付。Next 3.0 插件使用本页所列的候选最低宿主。界面可使用 `.ob-button`、`.ob-surface-card`、`.ob-input`、`.ob-select` 等公共样式钩子；自定义 CSS 可以补充其他选择器。设置页“恢复默认主题”及 `Ctrl+Alt+Shift+R` 为恢复入口，原生快捷键不受网页 CSS 影响。窗口、字体、装饰及动画的真实显示在最后统一人工验收。
