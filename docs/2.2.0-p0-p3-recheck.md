# Next 3.0 P0–P3 复核

2026-11-06。复核依据为 2.2.0 任务书第 16 部分的阶段清单，以及其中第 2、4–8、12、14、15 部分与 P0–P3 直接相关的要求。开发候选为 2.2.0-beta.1，公开正式版仍为 2.1.1。

## 版本与兼容策略

2.1.1 与初次 P3 使用相同的 Manifest/API 6 和 wire 4。对照发现旧校验器拒绝新取消帧，部分平台方法的允许执行上下文也已收窄。Next 3.0 采用单一版本切换，继续使用 uint32 大端长度前缀、UTF-8 JSON、stdin/stdout 和受管文件引用。新运行时握手校验固定的版本组合。候选包依赖的最低宿主由公共契约生成给构建工具，Rust 和 JS 校验器均拒绝低报。见 [首次复核](2.2.0-platform-review.md#p3-后版本复核) 与 [活动契约](../contracts/next2/contract.json)。

| 版本层 | 当前候选 | 后续修改规则 |
| --- | --- | --- |
| 宿主 | 2.2.0-beta.1 | 使用 SemVer。新包按使用的能力声明 `minHostVersion`，候选最低值为 2.2.0-beta.1。宿主版本低于声明时拒绝安装。 |
| Manifest | 7 | 更改现有字段含义或引入旧解析器不能理解的必需结构时评估升版。保留同版本时，为使用新增字段的包明确最低宿主并验证旧包到新宿主的路径。 |
| 运行时 API | 7，安装声明范围 `[7,8)` | 移除接口、收窄执行上下文或改变已有调用语义时升 API 主版本。新增能力按最低宿主或显式能力声明控制。 |
| IPC | wire 5 | 改变既有帧形状或含义时升 wire，除非只在双方明确支持的扩展路径启用。严格 Schema 下，不能向旧端主动发送未知字段。 |
| SDK 包 | JS API/UI 7.0.0-beta.1，CLI 3.0.0-beta.1，Rust 0.2.0-beta.1 | 各包分别管理发行版本。公共 JS 破坏性变化升主版本，Rust 0.x 的破坏性变化升次版本。版本号以包元数据和发布物为准。 |
| 插件包与 Capability | 插件各自的 SemVer、接口各自的 SemVer | 安装升级按插件包版本裁决，服务解析按接口版本范围裁决。接口输入、输出或语义不兼容时升 Capability 主版本。 |
| 宿主持久数据 | schema 1 | 存储结构变化单独管理迁移、恢复与数据校验。插件业务数据按稳定身份保留并由插件解释。 |

同一受支持版本内优先保留既有调用行为。需要弃用时先更新契约文档与测试，写清替代接口、支持范围及移除版本，再在相应主版本切换。候选发布前按下表复验允许与拒绝路径，并用发布形态插件跑安装和实际执行。生产回退应配对使用相应宿主和升级前已验证的数据备份。旧宿主、旧 SDK 与新版插件的任意混搭不在支持范围内。

| 组合 | 行为与证据 |
| --- | --- |
| 候选宿主 + Manifest 7 + API 7 + wire 5 | 安装、授权、运行和请求回包均通过。QuickJS 与独立 Rust SDK 原生 EXE 走实际子进程。 |
| 候选宿主 + 2.1.1 Manifest 6 或 wire 4/API 6 Worker | 安装拒绝 Manifest 6。旧已装记录停用并保留数据。实际发旧握手帧的子进程在初始化前被拒绝。 |
| 2.1.1 + 新 Manifest 或新 wire 帧 | 直接运行正式标签的 JS 校验器，Manifest 7 和 wire 5 均拒绝。此项验证校验器，未启动 2.1.1 桌面进程。 |
| Manifest 7 声明最低宿主 2.1.1 | Rust、JS 共享夹具均拒绝，构建模板默认写入候选最低宿主。 |
| 同身份升级 Manifest 6 到 Manifest 7 | 测试通过安装事务验证原数据库 ID、配置、KV 和用户文件，预览显示插件声明的迁移范围及说明。业务数据迁移由插件实现。 |

## 分阶段核对

| 阶段 | 任务书交付与本轮证据 |
| --- | --- |
| P0 源码与架构 | 核对宿主入口、安装、运行时、IPC、任务、存储、SDK 和独立插件的真实调用路径。原始基线、模块处置、技术选择、风险、协议、Capability 模型、路线和数据保护方案集中于 [平台审查](2.2.0-platform-review.md)。复核确认同号协议歧义，并按上表修正。独立插件仓库以 `f88efdc` 只读核查，压缩和环境管理使用各自的进程入口，MC 转换器经公开 API 请求代理路由。 |
| P1 契约与核心 | Manifest、接口 Schema、错误、权限、生命周期和请求共用生成源。宿主按安装身份、会话、权限和依赖声明路由。Capability 支持可选依赖、固定提供者或确定性版本选择、参数及结果验证、冲突与循环拒绝。补齐最低宿主校验和升级迁移信息的预览路径。JS 与 Rust 使用同一组契约夹具。SDK 包、CLI、独立模板和宿主的对应行为有可执行检查。 |
| P2 宿主与生命周期 | QuickJS 和原生 EXE 共用启动、握手、隔离和停止语义。Service 与 Task 实例独立，任务与普通调用共享已授权的持久数据。启停、依赖顺序、无页面服务、后台钩子、崩溃隔离与退出清理由真实 Worker 验证；两个隔离宿主测试进程先后打开同一 SQLite，验证后台恢复和正常退出。构建目录仅在开发模式下参与 runner 定位，分发模式只从宿主安装目录及其资源目录定位。 |
| P3 IPC、事件与任务 | RPC 响应关联、标准错误、会话内取消、Schema 事件订阅、文件分块、任务调度、结果与 Provider 协作均经过执行路径验证。复核补上页面桥接的取消通路，取消控制帧可在原调用挂起时抵达宿主。真实进程验证事件越权和队列溢出、180000 字节往返、文件修改及链接替换拒绝、任务超时及取消；任务库重开验证结果保留。 |

P0 对外部运行时的选型仍以可维护性和实际插件需求为准。Windows Python 嵌入发行包适合先验证离线资源方式。可按版本将发行包和锁定依赖装入插件的受管资源目录，以明确搜索路径启动，由同一进程监督器负责停止，诊断区分缺资源、ABI 不匹配和执行失败。候选验证需覆盖断网、更新回退、依赖隔离和多插件复用。Node 可用官方独立二进制，但还需解决依赖体积和原生模块 ABI。WASI 有受能力约束的文件访问模型，接入需要定义宿主导入与执行中断。三者均为设计评估，当前实际运行时为 QuickJS 和 Windows x64 原生后端。[Python 嵌入发行包](https://docs.python.org/3/using/windows.html#the-embeddable-package) · [Node.js 下载与签名校验](https://nodejs.org/en/download) · [Wasmtime 安全模型](https://docs.wasmtime.dev/security.html#filesystem-access)
