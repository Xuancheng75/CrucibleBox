# Next 3.0 数据迁移与恢复

Next 3.0 执行 Manifest/API 7、wire 5；旧 API 的安装记录、配置、KV、迁移标记与用户文件继续保留，旧代码不再执行。业务数据转换由同身份新版插件实现，宿主不按插件名称识别或重写业务表。

## 升级前

核对当前程序、数据目录、安装记录和更新目标，不以文件夹名称判断真实版本。必须先退出旧宿主及 worker；当前源码的 profile 锁只约束理解该锁的新宿主，不能替代对旧版进程的确认。

源码只用本地 Git 保存。重要用户数据的保护使用已有 SQLite 在线备份与程序/数据配对工具，不复制打开的数据库主文件当作完整备份，不从正式 Portable 启动测试实例。以下命令用于明确选定且已经停止的程序和隔离数据，真实生产操作需核对路径及当前发布授权。

```text
node scripts/next-paired-rollback.mjs capture <已停止的程序目录> <数据目录> <新的配对目录>
node scripts/next-paired-rollback.mjs verify <配对目录>
node scripts/next-paired-rollback.mjs restore <配对目录> <新的恢复目录>
```

工具要求输入与输出分离、新输出目录，拒绝覆盖已有目标，并对 SQLite 使用一致性备份。restore 的新目录是核验用暂存，不会重写数据库中的安装与结果绝对路径。先核对稳定身份、配置/KV、标记、文件与对应程序，再在旧程序停止后将数据归还原位置；不要直接将暂存目录当作可在任意路径运行的克隆，也不将旧程序直接配新版数据库作为受支持回退。

## 安装和插件迁移

安装预览确认发布者、版本、原生信任和权限差异。Manifest 的 dataMigration 写明适用旧插件版本及说明；确认页面展示它，不代表宿主已经执行业务迁移。插件使用私有配置、KV/事务和自己的版本标记；迁移与标记应在同一事务或已有发布机制中提交。

安装器通过 staging/journal/版本化目录与数据库配对恢复。中断、冲突和无法确定的状态明确失败或阻塞，不覆盖两个都有数据的源/目标。停用、升级和卸载先停止实例；卸载删除受管代码/独占资源，保留配置、KV、迁移标记和用户文件。

## 已测与未测

P0–P3 的自动用例验证保留 Manifest 6 记录并升级到 7、同身份数据访问、目录迁移冲突与安装中断恢复。P5/P6 验证两个真实候选的同代码包版本升级、停用和卸载重装，实际用户文件及私有数据保留。不能推广为任意插件 schema 迁移、生产数据升级或任意跨版本降级通过。

P7 的 beta.5 已完成隔离程序/数据配对捕获、核验与恢复暂存，再归还原测试数据位置，实际启动恢复出的程序；364000 字节业务正文、用户文件、后台自动恢复、历史任务与持久文件引用可读。该结果不覆盖任意数据目录重定位或生产数据升级。正式 Portable 未修改，其他边界见 [测试清单](testing.md) 与 [发布说明](release-runbook.md)。
