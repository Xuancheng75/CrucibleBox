# 2.1.1 四种卡片、选择对比与旧新页交接修正

**后续交付：** 2026-11-05 已发布 2.1.1，主题管理 1.0.9 调整为 95% 黑底，见 [正式发布记录](2.1.1-release.md)。本文保留上轮 1.0.8 的真实证据，不替代本轮制品身份。

2026-11-04。根据本轮三张实际截图，处理目录预览选择不明确、设置四区域同形、市场/任务卡片单调、任务标签红字混入背景，以及只播放新页进入动画的问题。

- 目录选中行改为白框红底白字并显示勾选提示，按钮提供 aria-pressed；不更改插件启用状态或顺序。
- 设置四区域分别采用折页、斜切、断角、票券四组轮廓，以及左脊、单线、双线、虚线标题装饰。主要面板仍为白边、85% 黑底、白字；应用信息标签去掉红色大底块。
- 市场与任务用同一四种设计均衡混排，条目顺序不变；按完整条目集合稳定分配，排序和普通刷新不跳变，市场筛选使用完整目录的分配。完整集合新增/移除条目时会重新分配。市场两列等宽、同行拉齐保留。
- 任务/运行日志标签使用黑底白字，选中项有白框与白色标线，不再用红字落在红色背景上。
- 交接使用浏览器同文档 View Transition，命名内容视口临时保留旧页图像，新 DOM 同步提交后接入新页图像；不克隆、搬移或重新挂载 iframe。旧页先启动，新页延后约 60ms 沿同一方向跟入，总时长约 520ms，动画不改变透明度或颜色。方向仍为主导航按上下顺序、插件左进右返。壳层固定，内容区在交接时短暂不接收操作，侧栏/顶栏可以打断并选择新目标，避免对旧图像误触底下新页。
- 同一事件的页面和插件变更合并提交；后来的导航取代尚未提交的旧目标，关闭活动插件使旧目标失效。更换主题结束正在播放的交接；减少/关闭/无过渡及不支持该能力时直接导航。新样式语法只放行长度受限的简单名称参数，其余 Raw、变量动画名、资源/权限和 CSS 预算限制继续保留。

方案依据：[Chrome 同文档过渡说明](https://developer.chrome.com/docs/web-platform/view-transitions/same-document)。本机已只读查询该 API、命名视口和旧页伪元素支持；没有用该探针切换原生页面。宿主源码 `aa5f1ed`，主题管理 1.0.8 构建源码 `bea0eec`。两处品牌标示、字体原件和许可保留；API 6 / wire 4 不变，没有插件名称专属判断。
