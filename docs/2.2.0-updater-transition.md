# 2.2.0 签名更新安装切换验收

2026-11-13。状态：测试实现已通过编译、fmt、Clippy 与执行器语法/lint 检查；用户已明确回复“允许仅在云端临时虚拟机测试”。尚待签名 Release 草稿产生后执行，未将源码检查算作安装通过。

项目 [AGENTS.md](../AGENTS.md) 的验证约定为“不运行系统安装器测试”，同时本轮目标要求正式签名更新的真实安装切换。因此本机保持该禁令；下述云端例外必须取得明确决定，不能将编译、签名文件存在或下载成功算作安装切换通过。

手动工作流 [.github/workflows/updater-transition.yml](../.github/workflows/updater-transition.yml) 默认不启用安装测试。允许后，仅在 GitHub 托管的一次性 Windows 虚拟机执行，结束后机器销毁；不在用户电脑安装任何系统实例，不更改本机 Portable 或防护设置，不接触本机数据及插件私有源码。

具体步骤：

1. 下载既有公开 2.1.1 安装器、执行者明确指定的旧 API 6 JavaScript 插件分发包及其公开摘要，核对后在虚拟机安装。实际启动旧宿主，通过公开 IPC 导入插件、写入真实 KV 与设置，再留下隔离用户文件及迁移标记夹具。宿主验收工具不内置业务插件名称/版本映射。
2. 下载对应 2.2.0 Release 草稿的安装器、minisign 签名和 Portable；不提前发布草稿或切换稳定渠道。
3. 非分发测试程序使用与宿主锁文件相同的 tauri-plugin-updater 2.10.1 和正式公钥。仅 Tauri 外壳为 MockRuntime；下载、签名校验和 Windows NSIS 安装均为生产组件真实实现。测试回环服务提供已下载附件，产品的 HTTPS/TLS 设置不变。
4. 先翻转安装包末尾一个字节，必须由 minisign 拒绝且不执行。正常包通过生产更新组件的下载与签名校验后，调用其实际安装入口，等待安装切换并实际启动新宿主。
5. 核对实际版本、两个程序与 Release Portable 相同、设置/安装记录/配置/KV/迁移标记/用户文件完整保留，旧 API 6 插件停用而数据保留。输出 JSON 证据；失败时保留失败而不补写通过。

本测试范围是生产更新组件及安装器的真实切换，不能称为在旧版设置界面人工点击更新按钮。源码见 [测试程序](../scripts/updater-transition/src/main.rs) 和 [执行器](../scripts/updater-transition/run.mjs)。执行器及 Rust 程序都要求 GitHub 托管环境和显式批准开关；常规测试不会自动执行安装。
