# Next 3.0 P3 IPC、事件与任务

P3 沿用 Manifest/API 6、wire 4 和数据 schema 1。请求、响应、平台方法和运行时帧由 [公共契约](../contracts/next2/contract.json) 生成 JS、TypeScript 和 Rust 类型。宿主从会话推导调用来源及权限，用请求 ID 关联响应。已准入的失败响应使用 `{code, message}`，无效传输或断开由传输层报告。

## 请求取消与任务

- Renderer 可向 `api.backend(method, params, { signal })` 或 `api.service(id, method, params, { signal })` 传入 `AbortSignal`。页面停止等待时向同一会话发送 `rpc.cancel`。宿主按请求 ID 取消关联执行，允许取消先于原请求到达，并拒绝迟到的原请求。普通请求默认执行期限为 30 秒。页面上的文件选择有独立交互期限。
- QuickJS 中断和原生 SDK 的 `Call::check_cancelled` 使用同一取消链。Worker 结束或进程树确认停止后，宿主才返回执行取消终态。正常退出、传输中断和超时分别进入现有进程监督路径。取消无法撤销已经提交的副作用，系统文件操作在返回控制权后才能检查取消状态。
- `tasks.start` 接受可选 `timeoutMs`，范围为 100 至 86400000 毫秒，从任务实际开始运行计时。省略时延续现有长任务行为。宿主把期限传给同一任务的 Provider 调用，超时记录为失败，错误码 `TASK_TIMEOUT`。手动取消沿用 `tasks.cancel` 和任务终态。队列、协作暂停与恢复、进度、输出发布及持久化结果继续使用既有 Task Runtime。重启可查阅已有任务结果，未完成执行按既有恢复规则处理。
- `tasks.start` 可指定 `{kind: "service", id: capabilityId}`。宿主用同一套依赖、方法和 Schema 校验来调度任务，按发起者归属保存结果。任务中的 Provider 通过上下文发布结果和进度，可使用受控文件引用，无需让调用方传递系统路径。

## 跨插件事件

Provider 在 `exports[].events` 声明 `{name, payload}`，其中 `payload` 是受支持的 Capability Schema。只有获得 `events:publish` 审批的后端能发布自身导出的事件。消费者声明服务依赖并获批 `events:subscribe` 后，按解析出的提供者及安装版本订阅。JS SDK 提供 `api.events.subscribe`、`publish`、`poll` 和 `unsubscribe`，原生 SDK 可调用同名平台方法。

每条载荷最多 8 KiB。每个会话最多 16 个订阅，宿主最多 128 个。订阅队列各保留最近 32 条，按该订阅的序号出队，`poll` 一次返回一条及本次累计丢弃数 `dropped`。队列空时 `event` 为 `null`。轮询续订五分钟空闲租期，释放会话、相关插件停用或被替换会清理订阅。事件只存在于当前宿主进程内。

## 大文件引用与分块传输

数据仍使用 64 KiB 长度前缀 JSON 帧。具备 `files:read` 的 JS 调用方可用 `for await (const chunk of api.readFileChunks(ref, { signal }))` 读取受授权文件。底层 `files.stream.open/read/close` 绑定发起会话，每次返回不超过 24 KiB 的原始数据及对应的 Base64、偏移和结束标记。调用方消费后再拉取下一块，提前退出迭代也会关闭句柄。每会话最多 8 个、宿主最多 64 个打开的流。会话结束、插件生命周期撤销或空闲租期失效后不能继续读取。

打开时比对实际句柄路径与授权路径，拒绝替换成符号链接的目标。读取前后检查文件大小及修改时间，发现变化时失效并报告 `FILE_STREAM_CHANGED`。流式读取不计算全文件哈希。已有持久化输出引用继续适用。可信原生后端可经既有授权用 `files.resolve` 获取路径，在本进程处理文件，避免分块编码。
