# 2.2.0 P7 依赖安全核查

2026-11-07。这是 npm 锁定依赖告警的实测与处置，不等同于二进制反病毒扫描，也不替代原 cookie 构建脚本的专家复核。

初次检查根项目为 5 个高危、24 个中危，前端为 2 个高危；未检出严重级别。beta.5 的长测因此在 22 分钟后停止，不能作为一小时通过。beta.6 使用下列补丁重新构建并固定验收。

最终 npm audit --audit-level=high：根项目与前端均返回 0。根项目仍有 22 个中危传播项，全部来自开发校验链上的同一个 [minimatch 模式放大公告](https://github.com/advisories/GHSA-g3hv-75wg-m249)；前端依赖审计为 0 告警。原始 JSON 在 .workbench/2.2.0-p7-beta6/npm-audit-*-final.json。

minimatch 告警要求攻击者控制 glob 模式且使用相应优化级别。本项目这些模式来自受控的 ESLint/TypeScript 源码扫描配置，不接收工具箱用户文件或插件传入的模式；开发校验工具不装入运行分发。现有上游要求的版本范围尚不能直接采用 11.0.1，npm 给出的自动修复涉及校验工具跨大版本回退。本轮不强制覆盖不支持的依赖范围；保留该限制，后续在校验工具支持时升级。该判断不应被写成“所有依赖零漏洞”。

两个业务候选只更新本轮所用的构建工具安全补丁，未扩展到其他插件。业务依赖的剩余告警与 UI 兼容性边界记录在独立仓库；宿主报告不代替其业务安全结论。

本轮更新没有使用 npm audit fix --force，没有把 Dev Server 部署进桌面运行版，也没有改变 Manifest 7、API 7、wire 5。具体候选构建和固定宿主结果见 [P7/P8](2.2.0-p7-p8.md)，原反病毒事件见 [事件记录](2.2.0-security-incident-20261107.md)。

2026-11-13 正式候选重新查询：根项目为 9 个中危传播项、0 高危/严重，前端为 0 告警。9 项仍来自上述 minimatch 同一公告及 ESLint/TypeScript 开发校验依赖链；没有通过强制覆盖或自动跨版本回退隐藏告警。当前 JSON 位于 .workbench/2.2.0-final/npm-audit-root.json 与 npm-audit-frontend.json。历史 beta.6 的 22 项是当时结果，不能当作当前数量。二进制扫描和这项依赖公告审计分别记录。
