# Next 3.0 P7/P8 执行记录

当前源码正在补完原任务书，候选为 2.2.0-beta.7，尚未完成验证或正式交付。beta.6 的既有结果仅是历史本地候选证据，不能据此宣布原任务书全部完成。进度见 [补完记录](2.2.0-completion-audit.md)。

2026-11-07 实测，2026-11-08 完成交付留档。当前固定候选为 2.2.0-beta.6，源码保存于本地提交 1f471cb。P7 的下列固定宿主验证、完整小时和用户原生回执，以及 P8 本地候选交付已完成；公开发布、稳定渠道和正式 Portable 替换未执行。

## 本轮实现

- 按用户要求删除 Windows 原生“外观”菜单创建、菜单事件和隐藏逻辑。主题恢复保留设置页与独立 Ctrl+Alt+Shift+R，快捷键只在主窗口有焦点时处理。用户于 2026-11-08 回执启动显示、主题恢复及正常关闭重开均通过。
- 实际复现 beta.3 同一 APPDATA 下两个宿主同时打开 SQLite。增加进程存活期排他文件句柄；不同 profile 互不排斥，退出后由 OS 释放，不依赖删除锁文件。
- 原优化构建的 cookie 构建脚本被 Kaspersky 删除两次，用户的 OpenTIP 页面仍报 Malware 且没有复核入口。用户明确要求调整工具箱实现继续 P7/P8。固定 cookie 0.18.2 原版运行库，只关闭 nightly 文档探测脚本；13 个库源码文件不变，保留许可和升级复查要求。原对象不恢复、不重建、不放行，也不认定为误报。见 [安全记录](2.2.0-security-incident-20261107.md) 和 [来源说明](../src-tauri/vendor/cookie/ORIGIN.md)。
- beta.4 替代候选在 16 页面挂载时暴露数据库短暂竞争。beta.5 将 create_next_renderer_session 的两次数据库访问改为现有串行锁处理，避免正常后台写入造成瞬时 BUSY；不在测试或产品中自动重试掩盖失败。
- beta.6 更新已公布修复的构建依赖并重新构建、固定及执行验收。根目录与前端的高危/严重 npm 告警均为零；根目录仍有 22 个中危开发工具传播项，不能写成全部告警清零。范围和处理依据见 [依赖安全记录](2.2.0-dependency-security.md)。
