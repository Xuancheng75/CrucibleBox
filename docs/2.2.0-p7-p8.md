# Next 3.0 P7/P8 执行记录

2026-11-07。当前源码候选为 2.2.0-beta.6，正在补齐依赖安全修复并重新固定。下列实测表记录 beta.5，不能直接计入 beta.6。原生人工结果未提供，P7/P8 未全面完成，也未正式发布。

## 本轮实现

- 按用户要求删除 Windows 原生“外观”菜单创建、菜单事件和隐藏逻辑。主题恢复保留设置页与独立 Ctrl+Alt+Shift+R，快捷键只在主窗口有焦点时处理。启动显示及键盘操作仍待用户验收。
- 实际复现 beta.3 同一 APPDATA 下两个宿主同时打开 SQLite。增加进程存活期排他文件句柄；不同 profile 互不排斥，退出后由 OS 释放，不依赖删除锁文件。
- 原优化构建的 cookie 构建脚本被 Kaspersky 删除两次，用户的 OpenTIP 页面仍报 Malware 且没有复核入口。用户明确要求调整工具箱实现继续 P7/P8。固定 cookie 0.18.2 原版运行库，只关闭 nightly 文档探测脚本；13 个库源码文件不变，保留许可和升级复查要求。原对象不恢复、不重建、不放行，也不认定为误报。见 [安全记录](2.2.0-security-incident-20261107.md) 和 [来源说明](../src-tauri/vendor/cookie/ORIGIN.md)。
- beta.4 替代候选在 16 页面挂载时暴露数据库短暂竞争。beta.5 将 create_next_renderer_session 的两次数据库访问改为现有串行锁处理，避免正常后台写入造成瞬时 BUSY；不在测试或产品中自动重试掩盖失败。

## 长时测试与剩余人工边界

beta.5 长测记录了 22 分钟、6600 次调用，主进程私有内存约 18 MiB、句柄小幅波动。依赖审计发现上游已发布的高危修复后，主动停止该候选的测试驱动和隔离宿主，完整小时未完成。beta.6 使用修复依赖后须重新构建、固定、复验并从头执行一小时，不将阶段记录计作长稳通过。

启动菜单栏是否完全消失、主题恢复快捷键、设置页、缩放和焦点、插件操作、日志导出、正常窗口关闭重开仍需用户人工回执。没有 Computer Use、系统安装器或生产数据迁移结果。
