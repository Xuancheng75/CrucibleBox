## P1 能力契约与使用

平台沿用 Manifest/API 6、wire 4 和数据 schema 1。插件包版本、接口 SemVer 和宿主最低版本各自独立。使用下面新描述的正式插件将 `minHostVersion` 设为 `2.2.0` 或更新。P1 编译仍使用仓库中统一的宿主版本 2.1.1，隔离测试夹具与该编译版本对齐。

在 Provider Manifest 的 `exports` 中声明能力。

```json
{
  "id": "sample-sum",
  "version": "1.0.0",
  "interchangeable": true,
  "methods": [
    {
      "name": "sum",
      "params": {
        "type": "object",
        "properties": { "numbers": { "type": "array", "items": { "type": "integer" } } },
        "required": ["numbers"],
        "additionalProperties": false
      },
      "result": { "type": "integer" },
      "contexts": ["renderer", "backend"]
    }
  ]
}
```

消费者在 `dependencies` 中声明 ID 和 `version: { "min": "1.0.0", "maxExclusive": "2.0.0" }`。可选依赖允许缺失，调用缺失能力时仍会得到错误。省略 `providerId` 时只选择显式可互换的提供者，按接口版本降序、同版本插件 ID 升序决策。依赖固定身份或存储状态时指定 `providerId`。Provider 应按 SemVer 管理方法及 Schema，破坏性变更用新的主版本。宿主按声明的版本范围裁决，兼容语义由接口维护者负责。

JS 和 TS 使用 `api.resolveCapability('sample-sum')`，Rust 使用 `Client::resolve_capability`。返回值由公共契约生成，含 `providerId`、`providerVersion`、`lifecycle` 和 `export`。绑定代表当前注册和依赖解析结果。执行仍需检查安装版本、有效审批及载荷，Provider 的进程健康独立于绑定。调用示例见 [开发记录](2.2.0-platform-progress.md)。

Schema 支持对象、数组、整数、数值、字符串、布尔和 null。闭合对象声明 `properties` 与 `additionalProperties: false`，可以指定 `required`。数组必须指定 `items`，整数、数值、字符串和数组支持相应上下限。宿主拒绝 `$ref`、正则和未知关键字，保留清单与 IPC 的深度预算。每个能力描述另限 32 KiB 和 8192 个值节点。字符串方法仍可供已有插件使用，按原不透明负载语义执行。

调用权限来自通过审批的当前安装、已授权会话、消费方的依赖声明和方法 `contexts`。Manifest ID 用于运行时寻址，历史数据库记录 ID 继续标识配置、日志和任务归属。省略 `contexts` 时开放 renderer 和 backend 两种已授权来源。Provider 的宿主内建 API 权限来自自身安装，参数和 ServiceTarget 不能指定调用身份或越过宿主权限。普通 RPC 和 `tasks.start` 使用相同的参数校验，任务在入队前拒绝非法输入。Worker 返回后校验结果，再交给调用者或任务持久化。标准错误包括 `CONTEXT_DENIED`、`INVALID_CAPABILITY_PARAMS`、`INVALID_CAPABILITY_RESULT`、`PROVIDER_CHANGED` 和依赖解析错误。

| 自动化依赖方向 | [check-platform-boundaries.mjs](../scripts/check-platform-boundaries.mjs) 校验 Cargo 元数据，已接入现有 Windows Rust CI。检查平台 crate 的 Tauri 边界、本地依赖路径与 Rust SDK 的独立性。业务插件仓库的构建和适配验收归 P6。 |

| 宿主与真实 QuickJS | 宿主 fmt、Clippy 和 `custom-protocol` 构建通过。141 项宿主测试通过。安装无页面 Provider 后，验证发现、调用、任务入队前的参数拒绝、普通 RPC 和已运行任务的结果拒绝，以及包篡改、升级与日志归属。见 `host-test.log`、`host-build.log`。 |
| 原生与独立 crates | runner 6、runtime 7、Rust 协议 10 项通过，其余独立 crates 的既有测试及 Rust fmt/Clippy 门禁通过。宿主默认忽略的 6 项中，原生安装、取消、崩溃和升级用例使用 SDK 示例另行通过。其余 5 项联网或系统配置用例及 repository 的实际用户库夹具用例未计入通过。见 `host-native-integration.log` 与各 crate 日志。 |

| 数据保护 | 目标目录保留、旧数据库 WAL、事务回退和成对恢复夹具通过。生产目录切换、实际用户数据迁移和桌面人工验收归后续阶段。 |
