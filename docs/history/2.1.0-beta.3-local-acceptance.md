## 独立标注集首轮实测

采用 [ClinOCR-Bench v1.0](https://github.com/ClinOCR-Bench/ClinOCR-Bench)。其项目说明扫描图像逐份配对经过人工复核的转录文本，原始文本先从源 Word 文件抽取，再由人工审查。发行包 SHA-256 为 `ce1d231138050abf7f458ba5e6bd75c6ee2f3832b72f22296843da4c5ba45457`。本地只抽取三个样本，以 `scripts/prepare-clinocr-fixtures.py` 将原 JPEG 扫描图嵌入单页 PDF，保留同名真值 TXT；PDF 经 `pdftotext` 核实无文字层。完整样本来源和 SHA-256 见本地 `.beta3-tools/ocr-benchmark/fixtures/manifest.json`。样本及识别输出仅作本地验收，不纳入产品包。

运行实际 Tauri Rust 文档管线的 `exports_annotated_pdf_ocr_for_accuracy_scoring` 忽略测试，使用本机 `ppocrv6-small-det-v5-mobile-rec` CPU 模型；三个 PDF 均成功经 OCR 路线处理。以 `scripts/score-ocr-acceptance.py` 计算编辑距离，标准化规则为 Unicode NFKC、大小写折叠、空白合并：

| 样本                                  | 参考字符 / 单词 |      CER |      WER |
| ------------------------------------- | --------------: | -------: | -------: |
| 清晰扫描 `template_1_sample_2_normal` |     1,618 / 231 | 0.838690 | 0.952381 |
| 劣质扫描 `template_1_sample_2_poor`   |     1,618 / 231 | 0.825093 | 0.935065 |
| 表格 `template_9_sample_2_tables`     |     1,191 / 170 | 0.445844 | 0.588235 |

这些数值显示当前模型/文档管线在该英语样本上漏识别严重，不满足高精度验收。CER/WER 同时受版面阅读顺序和字段分隔影响，不能直接分离检测、识别与结构重建各环节误差。该标注集是合成临床文档，仅覆盖英语；仍需中文和表格关键字段标注集、高精度 PP-OCRv5 server + PP-StructureV3 模式，以及相同样本的前后对照。

随后将低内存默认路径改为同一 Python worker 内运行 RapidOCR 正文识别与 PP-DocLayout-M / PP-FormulaNet_plus-S ONNX 公式识别。2026-09-27 在上述三份人工校对 PDF 上重跑完整 Rust 文档管线，清晰、劣质、表格样本的 CER 分别为 **0.156984、0.618047、0.387909**，WER 分别为 **0.151515、0.709957、0.376471**。清晰页有明显改善，劣质页与表格仍不达高精度目标；这些结果不能外推到中文、长文档或全部布局。直调 RapidOCR 的清晰页 CER 约 0.085，与宿主导出的 0.157 差异提示阅读顺序和字段重排仍有损失。图片 OCR 入口现也使用该组合路径，需继续在安装包内验证。

2026-09-28 定位到宿主对 RapidOCR 已排序的文字块再次按坐标分栏，造成清晰页页眉、表格字段显著乱序。修复为保留 worker 原文字顺序，仅将公式候选插入相应页面位置，并提升 IR 缓存版本。对同三页重跑真实 Rust 管线，清晰、劣质、表格 CER 分别为 **0.084672、0.660692、0.010076**，WER 分别为 **0.095238、0.722944、0.011765**。低质页仍大量漏检。官方 PP-OCRv5 server 识别 ONNX 在这批英语样本上更慢且更差；server 检测 + 原英文 mobile 识别可把低质页 CER 降至 0.566131，但实测私有内存峰值 2.52–2.88GB，因此不能用作默认 2GB 模式。低内存小检测模型分块测试可把低质页 CER 降到约 0.54，仍未达高精度目标，暂不以样本特例写入产品。
