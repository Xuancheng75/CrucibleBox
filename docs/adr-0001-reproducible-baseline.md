# ADR-0001：可复现构建基线与插件源码布局

- 状态：已接受，2026-08-11 修订
- 日期：2026-08-09
- 里程碑：M1

## 背景

宿主源码与六个生产插件原先分别以 ZIP 交付。每个插件都有独立的
`package-lock.json`，但没有统一的 clean、检查、测试、打包和产物校验流程；多个
插件的 `package.json`、`package-lock.json` 与 `plugin.json` 版本也不一致。宿主 CI
只构建源码，没有真正打包和启动 Electron，原生模块重建失败还可能被忽略。

在建立安全边界、SDK v2 或升级 Electron 之前，必须先得到一个可重复验证的工作
基线，避免把历史依赖变化、目录重排和架构重构混在同一个不可审查改动中。

## 决策

1. 宿主保留在仓库根，六个插件放在 `plugins/<plugin-name>`。
2. 宿主和 `plugins/*` 组成 npm workspaces，仓库根 `package-lock.json` 是唯一依赖
   锁定事实源。宿主继续保留在根目录，不为了 workspace 搬迁现有代码。插件必须
   显式声明自身运行时依赖，构建和发布不得依赖未声明的隐式提升。
   React/ReactDOM 固定为迁移前六插件共同使用的 19.2.8，避免 workspace 提升改变
   已审计的自包含 renderer 和 UniEnv 受信服务摘要。
3. 所有插件构建必须先安全清空自己的 `dist`，再从 `src` 重建。
4. `scripts/plugin-catalog.json` 是发布文件白名单。发布器不扫描目录猜测文件，且
   强制使用规范化 ZIP 路径、固定条目顺序和固定时间戳。
5. 插件 ZIP 验证必须检查：三处版本一致、入口存在、没有路径穿越、文件集合与白
   名单完全一致、ZIP 内容与本次构建内容逐字节一致。
6. 宿主生产包排除插件源码、测试、文档、脚本、历史 ZIP 和构建制品。
7. CI 固定 Node 24.15.0 / npm 11.12.x，执行依赖安装、静态门禁、测试、宿主与插件
   构建、插件打包校验、Electron unpacked 打包以及隐藏窗口启动冒烟。
8. 原生模块 ABI 重建失败必须使安装或流水线失败，不再允许“跳过并继续”。
9. 项目级 `.npmrc` 固定官方 npm registry；根 lockfile 的远程产物只允许
   `registry.npmjs.org`，同时依赖 `integrity` 做逐包内容校验。

## 结果

- 六个插件均可从空 `dist` 干净重建并生成确定性 ZIP。
- 根目录一次 `npm ci` 安装宿主和六个插件依赖，不再逐插件执行独立安装。
- 连续两次打包产生相同 SHA-256。
- 宿主可生成 `release/win-unpacked/CrucibleBox.exe`，并已验证数据库初始化和
  renderer 加载。
- M1 没有修改数据库结构、用户目录或已有用户数据。

## 明确延后

- Electron 34、electron-builder 25 和相关依赖升级在 M2 独立处理，避免与基线混改。
- 当前插件子进程仍是完整 Node 进程，renderer 插件仍与宿主共享 document；它们不
  是可靠安全沙箱。M2 必须建立真正的渲染隔离和可强制执行的能力边界。
- 插件签名、SBOM、来源证明、原子安装/升级回滚属于后续供应链里程碑。
- 格式化门禁当前是渐进式范围，只覆盖本轮新增编排脚本、测试和插件构建配置；不
  在 M1 一次性重排整个历史代码库。
- 当前只验证 Windows x64 unpacked 产物。签名安装器和 macOS/Linux 矩阵在发布里
  程碑处理。

## 重点插件后续顺序

在不改变宿主数据协议的前提下，先做两个可独立回滚的小里程碑：

1. GIF Editor 正确性与资源预算：非方图旋转、disposal、统一画布尺寸、监听器/滤镜
   提交、历史与缩略图一致性，并补像素级金样例。
2. UniEnv 安全止血与任务协议：运行时输入校验、路径边界、去动态 shell 拼接、组合
   安装 taskId/取消/互斥，并补离线单测。

随后进入宿主 M2 安全边界与 Electron 升级；UniEnv 作为第一方高权限插件继续迁移
到窄化、可审计的宿主能力，而不是向普通插件暴露原始 shell。
