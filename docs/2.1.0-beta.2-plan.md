# CrucibleBox 2.1.0-beta.2 开发计划

本计划以用户确认的 beta2 方案为实施基线。目标是修复原生闪退、恢复 beta1 合并时丢失的完整功能，并开放无需修改宿主即可开发常见第三方插件的生态。名称应直接表达用途，旧插件数据保留且迁移可重复执行。

## 工作顺序

1. **B2-00 基线与稳定性**：保护当前源码和 `%APPDATA%\cruciblebox`；对照源码、便携版、已发布插件；分析 Windows `0xc0000374` 崩溃，修复实际原生调用链；提供仅本地保存、可导出的故障记录。
2. **B2-01 开放宿主与市场**：Manifest/SDK v4 兼容 v2/v3；将插件标签、关键词、命令、文件处理、设置、任务、插件间服务变成扩展契约；实现细粒度本地进程授权；开放 HTTPS 第三方目录和本地开发插件；升级目录 schema v2 并兼容 v1。
3. **B2-02 标签与搜索**：数据库 v6 保存多对多用户标签；官方/第三方功能标签只读，用户标签可编辑；市场与主页共用搜索弹窗和主题样式；文本搜索与标签筛选组合。
4. **B2-03 功能恢复**：以成熟旧实现为基础升级“日记与笔记”“剪贴板管理”“随机决策”“汇率与单位换算”“GIF 动画编辑”“数据格式转换”“压缩与解压”；将 `media-toolkit` 定位为图片处理，建立真正的音视频处理插件；`developer-toolkit` 定位为接口调试。不能直接重发旧 ZIP。
5. **B2-04 文档与知识库**：补齐 PDF 合并/重排/旋转/图片提取/可搜索 PDF；轻量 OCR 保留，按需安装独立本地高精度模式；可视化 OCR 纠错与完整 RAG 预处理；桌面 PDF 和新增人工标注样本对比准确率。
6. **B2-05 本地交付**：逐插件真实操作与数据迁移验收；同步源码、插件包及 `E:\CruibleBox_Portable\CrucibleBox`；不自动发布 GitHub。

## 数据与兼容

- 插件清单和市场目录都以稳定插件 ID 识别，用户显示名称、分类和多个标签分开保存。第三方目录安装记录原目录；更新只使用原目录，同名冲突必须显式选择。
- v6 增加用户标签表、插件标签关系和插件来源信息。已安装旧插件及 beta1 合并插件的数据不删除；反向迁移由目标插件首次启用时幂等完成，直到用户确认结果。
- 插件扩展点以声明式 Manifest 和版本化 SDK 提供。新增业务插件不应要求改宿主身份映射；新的操作系统能力仍需宿主实现和授权。
- 不新增 SHA-256、哈希校验、形式化门禁或冒烟框架；保留插件权限确认和应用已有的签名更新机制。

## 验收重点

- 本地原生闪退不再复现；插件侧故障不会退出主程序。现有崩溃记录：2026-09-20 09:36，本地便携版 `cruciblebox.exe`，异常码 `0xc0000374`。
- 旧日记、GIF 和剪贴板数据与操作路径在新版可继续使用；综合插件不再以简化页面替代成熟功能。
- 市场和主页搜索、六种主题、标签的跨重启保留与筛选结果一致；自建目录能独立完成插件安装、授权、更新、卸载。
- OCR 使用人工标注样本计算字符错误率与表格关键字段正确率。问题样本总体字符错误率相对 beta1 降低至少 25%，清晰印刷中文不回退，表格关键字段正确率达到 90% 以上；达不到时如实展示限制。
