# Next 3.0 P2 执行宿主与生命周期

P2 延续 [P0/P1](2.2.0-p0-p1.md) 的权限和能力契约。QuickJS 与 Windows x64 原生代码共用 `Worker::launch`、长度前缀传输和 Windows Job Object。[Worker 实现](../src-tauri/crates/next2-runtime/src/worker.rs)

## 实例和状态

| 状态 | 状态来源与转换 |
| --- | --- |
| 已安装或停用 | 安装事务保存稳定插件 ID、批准清单与持久数据。停用选择存入数据库，Provider 退出发现。 |
| 已启用 | 可参与依赖解析。显式启用先验证依赖并启动后端，成功后保存启用选择。重启时未声明后台的服务按需加载。 |
| 启动中 | 每个插件和实例类型预留独立槽位，校验包和握手期间释放全局池锁。并发请求会收到 `BACKEND_STARTING`。 |
| 就绪 | 受监督的 Worker 已完成握手。普通调用使用 Service 实例，任务使用同插件的独立串行 Task 实例。跨实例状态通过持久存储传递。 |
| 停止中 | 维护标记阻止新执行。停止等待启动完成，先处理 Task，再处理 Service，确认进程树和任务停止后提交停用或卸载。宿主关闭时按可解析依赖逆序退出。 |
| 失败 | 启动失败不提交新启用选择。空闲退出和后台钩子失败会清理 Worker 并记入插件日志，保留已启用选择。新的显式调用可以重建实例。 |

健康检查在每个受管实例独立运行，避免一个缓慢的握手或后台执行阻塞其余实例。Provider 身份由宿主验证，原生代码仍属于可信本地代码。[生命周期实现](../src-tauri/src/next2_host/lifecycle.rs)

## 后台服务

`background: true` 使已启用服务在启动恢复后按依赖顺序启动。可省略 renderer。QuickJS 服务可同时声明 `backgroundIntervalMs`，范围为 1000 至 60000 毫秒，并从后端模块导出 `background(context)`。宿主仅在 Service 实例空闲时调度，钩子可通过同一受权会话读写存储和调用服务。普通调用与钩子串行执行。Task 实例不调度周期钩子。钩子失败会停止当前实例并留下错误记录。

`activate` 与 `deactivate` 分别属于握手和退出过程。需要调用宿主能力的 QuickJS 后台工作应放入 `background(context)`，在握手结束后执行。Native SDK 通过既有协议运行可信原生服务，周期钩子配置用于 QuickJS。

## 验证

P2 Windows x64 MSVC 验收通过。宿主 142 项通过，另外使用原生 SDK 示例单独通过安装、取消、崩溃和升级用例。真实 QuickJS 服务验证了无页面恢复、依赖启动、后台写入持久存储、钩子失败隔离和后续显式恢复。另有两个独立宿主测试进程依次读取同一隔离 SQLite，恢复服务、调用并正常退出，最终保留两次业务写入。runner 6 项、runtime 7 项、Rust 协议 10 项、SDK 51 项以及相关 Rust fmt 和 Clippy 门禁通过。

原始日志在 `.workbench/2.2.0-p2`。桌面界面由用户后续人工验收。宿主恢复测试以无界面进程执行，采用与桌面启动相同的后端恢复和退出路径。
