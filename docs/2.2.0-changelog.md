# 2.2.0 开发变更与交付状态

架构名称为 Next 3.0。当前固定候选 2.2.0-beta.6，P6 基线为 beta.3。P7 固定宿主、一小时及用户指定原生操作回执和 P8 本地候选交付已完成；本页不是公开正式发行说明。

## 已实现并有对应阶段证据

- Manifest/API 7、wire 5 及独立 SDK 版本，保留长度前缀传输、旧记录和用户数据；旧执行链停止。
- 声明式 Capability、版本/参数/结果/上下文验证、确定性依赖选择与坏包局部隔离。
- QuickJS/原生 Service 与 Task 生命周期、后台工作、事件、请求取消、文件分块和持久任务结果。
- 公共文件、网络、受管进程、存储配额、日志、资源与运行时基础能力。
- UI Contributions、主题协商、公开 UI/Provider SDK、独立创建/构建/检查/打包模板。
- 四类诊断插件和两个真实业务负载的固定宿主验收；业务材料留在独立仓库。
- beta.3 统一成功任务的持久完成时间，提交收尾窗口和实际重启精确对照通过。

来源为 P0–P6 各阶段文档；不将建议中的所有文件/网络扩展功能都宣称实现。

## beta.4 源码改动

- 复现同一 profile 两个 beta.3 宿主均打开数据库；增加进程存活期排他文件句柄，单元测试验证同目录拒绝与释放，不依赖删除锁文件。
- 按用户要求删除 Windows “外观”菜单创建、菜单事件和隐藏代码。恢复默认主题改用独立的原生快捷键处理，设置页入口保留。快捷键只在主窗口有焦点时响应；注册冲突明确记录，不阻止程序启动。
- 补充 API 索引、Provider、维护、测试、迁移和交付文档。

原优化构建被拦截后，用户授权采用运行库不变、关闭文档探测脚本的替代依赖配置。随后 beta.5 修复多页面创建时数据库瞬时 BUSY；beta.6 更新已公布修复的构建依赖并重新固定，通过宿主/runner 门禁、前端与 SDK 检查、优化构建和新程序扫描。64 插件/16 页面、10000 次有序及 16 路并发 RPC、64 MiB 传输、Provider 升级/故障、取消、超时及配对恢复有实际证据。一小时 18000 次调用完成；用户于 2026-11-08 确认无“外观”栏、设置页与快捷键主题恢复、正常关闭重开通过。便携及 SDK ZIP 解压后的独立安装、构建及真实调用通过。范围见 [P7/P8](2.2.0-p7-p8.md)，剩余开发依赖告警见 [安全核查](2.2.0-dependency-security.md)，原检测结论见 [安全事件](2.2.0-security-incident-20261107.md)。

## 正式冻结前

按真实支持范围和剩余告警冻结宿主/SDK/契约与配套包。未测的原生缩放/焦点、完整业务编辑器操作、日志导出、生产数据迁移、updater 签名及安装切换须分别验证，不由本轮四项用户回执替代。公开正式分发仍需对应授权；当前 GitHub 正式版及本机正式程序仍按既有 2.1.1 交付记录管理。
